# 棚卸：未確定の自動保存（下書き）が消える要因

**目的**: 確定完了時の対象グループ下書き削除を除き、下書きが意図せず消える要因を記録し、該当する不具合を修正する。

**確認日**: 2026-02-28

---

## 1. 下書きの保存設計

| パターン | ストレージキー | 備考 |
|----------|----------------|------|
| **単一グループの棚卸**（商品グループが1つの棚卸ID） | `PREFIX:{countId}:{locationId}:{groupId}` または `_single`（count 単位） | 2026-02-28 修正：従来の LEGACY_KEY 共有をやめ、**棚卸ID・ロケーション単位**でキーを分ける。復元時は LEGACY_KEY をフォールバック参照（後方互換）。 |
| **複数グループの棚卸**（商品グループが2つ以上の棚卸ID。まとめて表示・グループごと表示の両方） | `INVENTORY_COUNT_DRAFT_PREFIX:{countId}:{locationId}:{productGroupId}` | 棚卸ID・ロケーション・グループごとに別キー |

---

## 2. 修正した要因（2026-02-28）

### 2.1 複数グループの棚卸を確定したときに LEGACY_KEY まで削除していた（不具合）

- **整理**  
  - **複数グループ** = その棚卸IDが商品グループを2つ以上持っている状態。まとめて表示で確定する場合も、グループごとに1つずつ確定する場合も「複数グループの棚卸」です。  
  - まとめて表示で確定 ＝ その棚卸の**全グループを一括確定**なので、**その棚卸の下書きを削除するのは正しい**です。  
  - 複数グループの棚卸の下書きは **per-group キー**（`PREFIX:countId:loc:groupId`）にだけ保存されており、**LEGACY_KEY は使っていません**。LEGACY_KEY は**単一グループの棚卸**専用の共通キーです。

- **不具合だった点**  
  `clearAllInventoryCountDraftsForCount` が、複数グループの棚卸を確定したときに「その棚卸の per-group キー」に加えて **LEGACY_KEY も毎回削除**していました。  
  → その棚卸の下書き削除は per-group キー削除で完了しているのに、余計に LEGACY_KEY を消すため、**別の棚卸（単一グループ）の下書き**が消えていました。

- **修正内容**  
  - 複数グループの棚卸を確定したとき：**その棚卸の per-group キーだけ**削除（これまで通り。まとめて表示で全グループ確定時の削除として正しい）。  
  - **LEGACY_KEY は、確定対象が単一グループのときだけ**削除する（`productGroupIds.length <= 1` のときのみ LEGACY_KEY を削除）。  
  → 複数グループの確定では LEGACY_KEY を触らないため、別の単一グループ棚卸の下書きが消えなくなります。

- **該当**: `InventoryCountList.jsx` の `clearAllInventoryCountDraftsForCount`。

**まとめて表示の確定時**: その棚卸の全グループが確定するので、その棚卸用の per-group キー（`PREFIX:その棚卸ID:loc:group1` など）は**従来どおりすべて削除**しています。削除対象から外したのは「単一グループ専用の LEGACY_KEY」だけです。

---

## 3. 修正済み：単一グループ同士で下書きが上書きされる（2026-02-28）

### 3.1 単一グループも count 単位のキーで保存・復元・削除するように変更

- **事象**: 1つしかない商品グループの棚卸IDでも、保存・復元が行われない／別の単一グループ棚卸の保存で上書きされて消える事例があった。
- **原因**: 単一グループの棚卸はすべて **同じ LEGACY_KEY** に保存しており、棚卸Aの下書きを保存したあと棚卸Bを開いて編集すると、Bの自動保存で LEGACY_KEY が上書きされ、Aの下書きが消えていた。
- **対応**: 単一グループの棚卸も **棚卸ID・ロケーション単位**のキー（`inventoryCountDraftKeySingleGroup` = `PREFIX:{countId}:{locationId}:{groupId or "_single"}`）で保存・復元・削除するように変更。復元時はまずこの count 単位キーを参照し、無ければ後方互換で LEGACY_KEY を参照。確定時は当該棚卸の count 単位キーと LEGACY_KEY を削除。
- **該当**: `InventoryCountList.jsx`（保存 useEffect・復元ブロック・`clearAllInventoryCountDraftsForCount`）。

## 4. その他の確認結果（要因なし）

| 確認項目 | 結果 |
|----------|------|
| 確定時の下書き削除の範囲 | 確定した棚卸の per-group キー、および**単一グループのときのみ** LEGACY_KEY を削除。他棚卸の下書きは削除しない。 |
| 自動保存のタイミング | `lines` 変更から 300ms 遅延で保存。編集直後（300ms 以内）に画面を戻る・別棚卸を開くなどすると、**その回の変更は保存されない**。再度開いたときはストレージをそのまま読むため**「何もない」にはならず、最後に保存が完了した時点の内容（＝一つ前の保存）が復元される**。 |
| 下書きの読み込み | `countId` / `locationId`（単一のときは `productGroupId` も）が一致するときだけ復元。他棚卸の下書きは使わない。 |
| その他の delete/set | 棚卸下書き用の delete/set は `clearAllInventoryCountDraftsForCount` と自動保存の `storage.set` のみ。他に下書きを消す処理はない。 |

---

## 5. まとめ

- **修正1**: 複数グループの棚卸を確定したときに LEGACY_KEY を削除していた不具合を修正。これにより「別の棚卸（単一グループ）の下書きが、複数グループの棚卸を確定しただけで消える」事象は解消。
- **修正2（2026-02-28）**: 単一グループの棚卸も count 単位のキーで保存・復元・削除するように変更。これにより「1つしかない商品グループの棚卸IDで保存・復元されない」「単一グループ同士で下書きが上書きされる」事象を解消。
- それ以外に、確定完了時の対象の下書き削除以外で下書きを消している処理はない。
