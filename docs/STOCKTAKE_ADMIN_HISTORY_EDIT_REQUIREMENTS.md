# 棚卸：管理画面履歴からの編集・確定・キャンセル 要件まとめ

**作成日**: 2026年2月  
**対象**: 管理画面「棚卸」タブの「履歴」一覧で、棚卸IDをクリックして開くモーダル

---

## 1. 概要

現在は履歴モーダルは**閲覧専用**。以下を追加し、管理画面から数量編集・グループ/一括の確定・キャンセルができるようにする。

| 機能 | 概要 |
|------|------|
| 数量編集 | 通常は現仕様の表示。編集モードで未完了リストの実数を編集可能にする（または初めから入力枠の方が読み込みがスムーズならそちらを採用） |
| グループごとの確定 | 指定グループの全数量を在庫に反映し、リセット（取り消し）ボタンも用意 |
| 一括確定 | 全グループの全数量を在庫に反映し、リセット（取り消し）ボタンも用意 |
| グループごとのキャンセル | 未完了のグループのみ対象にキャンセル |
| 一括キャンセル | 全て未完了なら棚卸全体をキャンセル、一部完了済みなら未完了グループのみキャンセル |

---

## 2. 数量編集

### 2.1 表示方針

- **通常表示**: 現仕様どおり（在庫・実数・差分はテキスト表示のみ）。
- **編集モード**: 「編集」ボタン押下で、**未完了**のグループの商品リストについて「実数」が編集可能になる。
- **読み込みのしやすさ**: 初めから入力枠（input）を出した方がレンダリングやフォーカスがスムーズなら、その方式を採用する。どちらでもよい場合は「通常は表示のみ → 編集ボタンで入力可能」を採用。

### 2.2 仕様詳細

- 編集対象は**実数（actualQuantity）**のみ。在庫（currentQuantity）は変更しない。
- 編集可能なのは**未完了**グループの行のみ。完了済みグループは従来どおり読み取り専用。
- 「保存」で変更をメタフィールド（該当棚卸の `groupItems`）に反映する。
- 差分（delta）は「実数 − 在庫」で再計算して表示・保存する。

### 2.3 UI

- 履歴モーダルに「編集」ボタンを追加（例: モーダル下部のCSVボタン近く）。
- 編集モード時: 未完了グループの実数列を `<input type="number">` 等で表示し、「保存」「キャンセル（編集やめる）」を表示。
- 保存後は編集モードを解除し、通常表示に戻す。

---

## 3. グループごとの確定

### 3.1 概要

- 対象: モーダル内の**1つの商品グループ**。
- そのグループに紐づく全商品の「実数」を在庫に反映する（api/log-inventory-change で棚卸種別の変動記録 + 該当グループの groupItems をメタに保存して完了扱いにする）。

### 3.2 仕様

- 対象グループは**未完了**のものに限定。完了済みグループには「確定」ボタンは出さない（または無効）。
- 確定時: そのグループの全行について `currentQuantity` と `actualQuantity` の差分で在庫調整を実行（POS の確定処理と同様）。
- 確定後、そのグループは「完了済み」として表示し、履歴・一覧の進捗（X/Yグループ完了）を更新。

### 3.3 リセット（取り消し）

- 「リセット」ボタン: **そのグループについてだけ**確定を取り消す。
  - 在庫を元に戻す: 確定時に反映した差分の**逆**を api/log-inventory-change で記録（または専用の「棚卸確定取り消し」ロジック）。
  - メタ上はそのグループを再び「未完了」に戻す（groupItems から該当グループ分を削除するか、未完了状態に戻す）。

### 3.4 UI

- 各**未完了**グループのブロックに「このグループを確定」ボタンを配置。
- **完了済み**グループのブロックに「リセット」ボタンを配置（確定取り消し用）。

---

## 4. 一括確定

### 4.1 概要

- 対象: その棚卸に紐づく**全商品グループ**。
- 未完了グループについて、全商品の実数を在庫に反映する。

### 4.2 仕様

- 未完了グループを順に、グループごとの確定と同じロジックで在庫反映 + メタ保存。
- 全グループ完了後、棚卸ステータスを「完了」にする。

### 4.3 リセット（取り消し）

- 「一括リセット」ボタン: **この棚卸で確定した在庫反映をまとめて取り消す**。
  - 全グループ分の確定を逆順（または整合が取れる順）で取り消し、在庫を元に戻す。
  - メタ上は全グループを未完了に戻し、棚卸ステータスを「処理中」等に戻す。

### 4.4 UI

- モーダル下部（または履歴モーダルのアクション欄）に「一括確定」ボタンを配置。
- 全グループ完了後は「一括リセット」ボタンを表示（取り消し用）。

---

## 5. グループごとのキャンセル

### 5.1 概要

- 対象: **未完了のグループのみ**。そのグループを「キャンセル」扱いにする。

### 5.2 仕様

- 未完了グループに「キャンセル」ボタンを配置。
- 押下時: そのグループは「キャンセル済み」として扱う（在庫は変更しない）。
  - メタ上、該当グループを完了にも確定にもせず、キャンセル済みフラグを立てるか、グループを一覧から外す等の扱いにする。
- 完了済みグループはキャンセル対象外（ボタン非表示または無効）。

### 5.3 UI

- 各**未完了**グループのブロックに「このグループをキャンセル」ボタンを配置。

---

## 6. 一括キャンセル

### 6.1 概要

- その棚卸全体に対するキャンセル操作。完了状況に応じて挙動を分ける。

### 6.2 仕様

| 条件 | 動作 |
|------|------|
| **全て未完了** | 棚卸全体をキャンセル（ステータスを「キャンセル」に。在庫は変更しない）。 |
| **一部でも完了済みがある** | 未完了のグループのみキャンセル。完了済みグループはそのまま。在庫は変更しない。 |

### 6.3 UI

- モーダルに「一括キャンセル」ボタンを配置。
- 実行前に確認ダイアログで「全て未完了のため棚卸全体をキャンセルします」または「完了済み以外のグループをキャンセルします」と案内する。

---

## 7. 実装時の共通方針

- **管理画面**: `app/routes/app.inventory-count.tsx` の action に以下を追加する想定。
  - 数量編集保存: `update_stocktake_quantity`（該当 count の groupItems のみ更新）
  - グループ確定: `confirm_stocktake_group`（在庫反映 + メタ更新）
  - グループ確定リセット: `reset_stocktake_group`（在庫を戻す + メタで未完了に戻す）
  - 一括確定: `confirm_stocktake_all`（全未完了グループを確定）
  - 一括リセット: `reset_stocktake_all`（全確定を取り消し）
  - グループキャンセル: `cancel_stocktake_group`（未完了グループのみ、メタ上キャンセル扱い）
  - 一括キャンセル: `cancel_stocktake`（全体または未完了のみ、上記ルール）
- **在庫反映**: 既存の `api/log-inventory-change`（棚卸種別）を利用。管理画面からは fetch で呼ぶ（認証は loader の admin セッションを利用）。
- **リセット時の在庫**: 確定時に記録した変動の逆を記録する（delta の符号反転で api 呼び出し）か、専用の「取り消し」種別を検討する。
- **UI・文言**: 入出庫・ロス履歴モーダルおよび `docs/ADMIN_UI_DESIGN_RULES.md`（存在する場合）に合わせる。

---

## 8. まとめ一覧

| 機能 | 対象 | 在庫操作 | リセット/キャンセル |
|------|------|----------|----------------------|
| 数量編集 | 未完了グループの実数 | 保存時はメタのみ（確定ボタンで反映） | 編集キャンセル（未保存なら元に戻す） |
| グループごとの確定 | 1グループ | 全数量反映 | そのグループの「リセット」で在庫戻す |
| 一括確定 | 全グループ | 全数量反映 | 「一括リセット」で全反映を取り消し |
| グループごとのキャンセル | 未完了の1グループ | なし | そのグループをキャンセル扱い |
| 一括キャンセル | 棚卸全体 or 未完了のみ | なし | 全て未完了→全体キャンセル／そうでない→未完了のみキャンセル |

この要件に基づき、画面仕様と API/action の詳細を詰めた上で実装する。
