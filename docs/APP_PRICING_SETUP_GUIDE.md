# アプリの価格設定：具体的な手順

**目的**: Shopify パートナーダッシュボードで、公開アプリの価格を**具体的にどう設定するか**を手順としてまとめています。

---

## 1. どこで設定するか

- **パートナーダッシュボード** → **Apps** → **対象アプリ名** をクリック
- 左サイドバー **「配布」**（Distribution）
- **「提出を管理」**（Manage submission）または **「価格」**（Pricing）関連の項目

※ 画面表示は「配布」配下の **Pricing content** や **Manage listing** から **Pricing** に入る場合があります。英語表示では **Distribution** → **Pricing** または **Manage** → **Pricing content** → **Manage** で価格一覧（Pricing index）を開きます。

---

## 2. パターンA：無料で提供する（審査を先に通す場合）

**やること**

1. 上記のとおり **配布 → 価格** の画面を開く。
2. 価格の種類で **「Free to install」**（無料でインストール）を選択する。
3. 保存する。

**ポイント**

- 紹介文・スクリーンショット・アプリの詳細には**料金を書かない**（Shopify ガイドライン）。

**⚠️ 将来有料化する予定なら「いったん無料で審査」はおすすめしない**

以下の理由から、**有料化する前提なら、最初から有料プラン（またはフリーミアム）を設定して審査に出す**方がよいとされています。

| 理由 | 説明 |
|------|------|
| **課金フローの審査が二度手間** | 無料で通したあと有料化すると、その時点で課金フロー（Managed pricing のプラン選択・承認）の審査やチェックが再度必要になる。最初から有料プランを出しておけば1回で済む。 |
| **既存ユーザーへの課金切り替えが厳しい** | 無料でインストールしたマーチャントに後から「有料になります」とすると、**新しい課金への同意を各自がクリック**する必要があり、そのタイミングでアンインストールが増えやすい。 |
| **有料でも審査は問題ない** | 審査側は**テスト課金**（test モード）で課金フローを確認するため、有料プランでも審査が遅れたり通りにくくなったりはしない。 |

**おすすめの価格戦略（有料化する場合）**

- **戦略A：無料トライアル付き有料**  
  月額を設定し、**14日間や30日間の無料トライアル**を付ける。インストールのハードルは低く、トライアル終了後に自動で課金開始。設計書の Lite（7日）・Pro（14日）トライアルがこれに該当。
- **戦略B：フリーミアム**  
  **無料プラン1つ**（基本機能）と**有料プラン**（高度な機能・上限解放）を最初から用意して審査に出す。マーチャントは無料のまま使うか、有料でアップグレードするかを選べる。

「とりあえず審査だけ通したい・永続無料で提供する」場合のみ、Free to install のまま提出する選択でよいです。

### 2a. 無料で登録する場合の「公開プランを追加」フォームの入力

Managed pricing で「無料プラン1つだけ」を用意する場合、**公開プランを追加**で次のように入力します。

| 画面の項目 | 入力する内容 |
|------------|----------------|
| **内部計画ハンドル** | `free` または `free_plan`（30文字以内・後から変更不可。英小文字・数字・アンダースコア） |
| **請求する** | **「無料」**（Free）を選択 |
| **月額料金** | `0` のまま（無料なら入力不可や非表示になる場合あり） |
| **年間料金** | `0` のまま（同上） |
| **無料トライアル期間** | `0`（無料プランなのでトライアルは不要） |
| **リダイレクトURL** | `/app` または `/app/settings`（インストール後に開くアプリ内のパス） |

保存後、**表示名・特徴**を言語ごとに設定する場合は、例として次のようにします。

- **表示名**: 「無料」「Free」など
- **特徴**: 使える機能を短く（例: 出庫・入庫・履歴・CSV など）

※ 画面によっては「Free to install」を選ぶだけでプラン追加が不要な場合もあります。そのときは上記フォームは使わず、価格を「無料でインストール」に設定して保存するだけです。

## 3. パターンB：有料にする（Managed pricing）

Shopify の **Managed pricing** を使うと、Billing API を書かずにパートナー画面だけでプランと料金を設定できます。月額・年額・無料トライアルに対応しています。

### 3.1 Managed pricing を有効にする

1. パートナー → **Apps** → **対象アプリ** → **配布**（Distribution）
2. **価格**（Pricing）関連の **Settings** または **Manage** を開く
3. **Pricing content** の **Manage** で価格一覧ページを開く
4. 価格の方式で **「Managed pricing」** を選択する（新規公開アプリは初期から Managed pricing のことが多いです）
5. 既に Billing API で作成したプランがある場合は、Managed pricing に切り替える前に**削除**する必要がある場合があります

### 3.2 プランを追加する（Public plan）

**公開プラン**は最大 **4つ** まで。App Store とプラン選択ページの両方に表示されます。

1. 価格一覧画面で **「Public plans」** → **「Add」**（追加）をクリック
2. **プランエディタ**で次を設定する：

| 項目 | 内容 |
|------|------|
| **Billing** | **Free**（無料） / **Monthly**（月額） / **Yearly**（年額） / **Monthly with yearly option**（月額＋年額オプション）のいずれか |
| **Monthly charge** | 月額の場合、金額（例: 19.00）。通貨はストアの国などに応じて表示される |
| **Yearly charge** | 年額プラン or 年額オプションを使う場合、金額（例: 190.00） |
| **Free trial duration** | 任意。トライアル日数（例: 7 または 14） |
| **Welcome link** | 任意。課金承認後に飛ばすURL（例: `/app` や `/app/settings`） |

3. **Save** で保存

### 3.2a 「公開プランを追加」画面の項目ごとの入力例

パートナー画面の「公開プランを追加」フォームで、**各項目に何を入れるか**を具体的にまとめています。

| 画面の項目 | 説明 | 入力例（Lite プラン） | 入力例（Pro プラン） |
|------------|------|------------------------|----------------------|
| **内部計画ハンドル** | コード内でプランを識別するID。**30文字以内・後から変更不可**。英小文字・数字・アンダースコア推奨。 | `lite_monthly` | `pro_monthly` |
| **請求する** | 課金サイクル。 | **「毎月の継続払い」**（月額のみ）がシンプル。年割引を出すなら **「毎月の継続払い、年間割引あり」** | 同上 |
| **月額料金** | 月額の金額（USD）。 | `19`（Lite 例） | `59`（Pro 例） |
| **年間料金** | 年額を選んだときの金額。「毎月の継続払い、年間割引あり」の場合のみ入力。年額＝月額×10〜12 などで設定。 | 月額のみなら `0`。年割引ありなら例: `190`（約2ヶ月分お得） | 同上。例: `590` |
| **無料トライアル期間** | トライアル日数。0でトライアルなし。 | `7`（7日） | `14`（14日） |
| **リダイレクトURL** | プラン選択完了後に販売者が飛ぶアプリ内のパス。 | `/app` または `/app/settings` | 同上 |

**入力のコツ**

- **内部計画ハンドル**は、将来アプリ側で `plan === 'lite_monthly'` のように判定するときのキーになるので、**短く分かりやすい名前**にしておく（例: `lite` / `pro`、ロケーション別なら `lite_3loc` など）。
- **請求する**を「毎月の継続払い」だけにすると、月額料金だけ入力し、年間料金は 0 のままでよい。
- **リダイレクトURL**は、管理画面のルート（`/app`）か設定画面（`/app/settings`）が無難です。先頭の `/` だけ付き、ドメインは不要です。
- 保存後、**表示名・特徴**は「プラン説明」や「公開言語ごとの編集」で別途設定します（3.3 参照）。

### 3.3 プランの表示名・特徴を設定する（各言語）

料金は全言語で共通ですが、**表示名**と**特徴**は言語ごとに設定します。

1. **Pricing content** で、追加したプランを選択する
2. **Published languages** で、**Edit** する言語（例: 日本語、English）を選ぶ
3. **Shopify App Store listing** の **Manage listing** を開く（または同じ画面内の「プラン説明」エリア）で：
   - **Display name**：プラン名（例: 「Lite」「ベーシック」「Pro」）
   - **Top features**：このプランで使える機能を箇条書き（例: 出庫・入庫・履歴・CSV）
4. 他言語も同様に **Edit** して表示名・特徴を入力
5. **Save** で保存

※ ある言語で説明を登録していないプランは、その言語のストアには表示されません。

### 3.4 複数プラン例（Lite / Pro の場合）

| プラン | Billing | Monthly | トライアル | 表示名（例） | 特徴（例） |
|--------|---------|---------|------------|--------------|------------|
| 1 | Monthly | $19 | 7日 | Lite | 出庫・入庫、入出庫履歴、CSV出力 |
| 2 | Monthly | $59 | 14日 | Pro | 全機能（在庫情報・仕入・ロス・発注・棚卸含む） |

ロケーション数で価格を分ける場合は、**別プランとして追加**します（例: Lite 〜3ロケーション $19、Lite 〜10ロケーション $39、…）。最大4プランまで。

### 3.5 開発ストアでのテスト課金

- Managed pricing では、**開発ストア**がプランを選択すると **テスト用のサブスクリプション** が作成され、実際の請求は行われません。
- 審査用デモストアでも、有料プランを選ばせて「プラン選択 → 承認」の流れを見せることができます。

---

## 4. 運用上の注意

- **価格の記載**は**価格セクションだけ**にし、紹介文・スクショ・アプリの詳細には料金を書かない
- **Managed pricing にしたあと**は、Billing API で**新規**の Recurring charge を作成できません。既存の課金はそのまま処理されます
- プラン名・金額・トライアル日数は、パートナー画面からいつでも変更可能（既存契約には規定に従って適用）
