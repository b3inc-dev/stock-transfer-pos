# 出庫依頼：画面・出庫・印刷の共通化要件

2026-11-26。利用者の「仕入に合わせる管理画面」「他タイルと共通のPOS UI」「通常出庫の踏襲」「POS Receiptで確認した印刷の踏襲」を、この実装の確認基準としてまとめる。

## 事実と確認の範囲

- 管理画面の参照元は現行の仕入と `docs/UI_RULES.md`。POSの商品行・数量・固定操作は現行ロスを参照する。
- 通常出庫と出庫依頼は、同じShopify Transfer／Shipmentの定義で出庫する。受領は既存の入庫で行う。
- 出庫依頼は、依頼の版・端末の作業権・サーバーの実行記録が必要。通常出庫の画面内ロックだけに置き換えず、確定前確認・途中再開・結果不明時の照合を維持する。
- 印刷送信は取置で現在使う `receiptPrinting.js`。機器補正はPOS Receiptから引き継いだ現行取置の `receiptPrinterProfile.ts` を共用する。旧POS Receiptのプリンタ未接続時ダイアログへのフォールバックは移植しない。
- 自動テスト・SDK確認・管理画面の表示確認と、POS実機・紙での確認は別に記録する。共通コードを使う事実だけで、出庫依頼の紙出力も検証済みとは扱わない。

## 操作の流れ

1. 管理画面で依頼を作成し、下書きとして保存する。保存だけではPOSへ表示せず、在庫も動かさない。
2. 詳細の「店舗へ依頼する」から、出庫元・移動先・合計点数を確認して公開する。
3. 出庫元のPOS「出庫依頼／処理・履歴」で依頼を開く。依頼書の印刷と作業開始は別操作。
4. 作業開始後は検品画面で、スキャン・商品検索・数量入力・差異理由・配送情報を登録する。検品の保存だけでは出庫しない。
5. 「出庫完了」で確認モーダルを開く。過少・過剰・依頼外の商品、依頼数・出庫数・差分・理由を表示する。「確認して出庫」までShopifyへの出庫書込みは行わない。
6. 実数量でTransferを作成し、Shipmentを発送中にする。250明細超は分割し、進んだ位置を保存する。通信結果が不明なら照合し、同じ出庫をそのまま再送しない。
7. 完了後は詳細へ戻る。印刷は保存済み依頼・実数量を使い、出庫を再実行しない。移動先では既存の「入庫」で受領する。

## 管理画面：仕入との対応

| 要件 | 実装・共通部品 | 確認点 |
| --- | --- | --- |
| 他メニューと同じサブメニュー | 依頼一覧／作成／設定、GuardedLink | 未保存の画面からの移動も共通の保護を使う |
| 一覧は左に条件、右に依頼行 | AdminBlock／PickList／StateBadge | 一覧全体を枠内スクロールにしない。選択肢だけ枠内スクロール。25件ごとのページ送り |
| 出庫元・移動先を全ロケーションから選ぶ | requestLocations／PickList | shopで範囲を限定。検索・複数選択・全てを共通部品で提供 |
| 作成は左に依頼条件と検索、右に商品明細 | Form／SaveBar／EditTable | 検索用の別Formを入れ子にしない。商品追加後の数量は右で編集。二重追加を防ぐ |
| 下書きと公開を分ける | 詳細のPublishRequest確認 | 最新版・下書きだけ公開可。作業中の追記は既存の追加専用制約を保持 |
| 詳細は明細を主、状態と操作を右 | 共通状態表示・操作ボタン | 依頼数／実数／差分／理由、配送と受領、操作履歴。受領操作は追加しない |
| 戻ったときも条件を保持 | 検証済みreturnTo | 同一アプリの一覧だけを許可し、外部URL・認証情報は引き継がない |
| 狭い画面でも操作可能 | 共通History-tableと1列レイアウト | 長いロケーション名・商品名・数値欄がはみ出さない |

## POS UI：ロスなどとの対応

| 要件 | 実際に共用する部品 | 出庫依頼固有の内容 |
| --- | --- | --- |
| 上部固定／中央だけスクロール／下部固定 | Page・Stack・ScrollBox／FixedFooterNavBar | 依頼番号・移動先・希望日とロケーションを固定部に表示 |
| 下部操作は3つまで | extensions/common/FixedFooterNavBar.jsx | 検品は「戻る／検品を保存／出庫完了」。印刷は詳細へ配置 |
| 商品名・バリエーション・SKU/JAN・画像 | StockyRowShell／ItemLeftCompact | 依頼数と検品数を分ける。未開始は未検品表示 |
| 同じ数量ボタンと数値入力モーダル | QtyControlCompact_3Buttons | 許可された上限・依頼外追加・差異理由を適用 |
| 検索中に古い候補を追加しない | 条件・依頼ID・画面の世代照合 | 入力変更時に候補を即時無効化。失敗と0件を分ける |
| カメラ／ハードウェアスキャン | 同じScanner API | 検品画面だけ購読。退出時に停止し、遅い応答も詳細の数量を変更しない |
| 共通のページ送り | ListPageControls／getListPageSlice | 依頼一覧25件、検品明細50件。検索候補と明細を混ぜない |
| 他タイルと同じタイル表記 | 出庫依頼／処理・履歴 | 対象がある場合は従来指示の「要対応 N件」を表示 |

ロスの旧API側の表示を変えず、固定操作の実体を共通ファイルへ移す。2026-07のPOSは対応する属性の分岐を使う。旧APIの非対応属性を新しい画面へコピーしない。

## 出庫完了：通常出庫との対応と境界

| 対象 | 対応 |
| --- | --- |
| Shopifyへの出庫 | 既存のinventoryTransferCreateAsReadyToShip／inventoryShipmentCreate／inventoryShipmentMarkInTransitの定義と共通stock helperを利用 |
| 配送 | 通常出庫と同じ配送会社の設定、追跡番号・URL・到着予定日を利用 |
| 在庫と入庫 | Transfer／Shipmentを正とし、既存入庫で受領。独自の直接在庫調整を重ねない |
| 再実行 | 依頼固有の版確認・preview token・端末claim・操作記録・チャンクのcheckpointを保持 |
| 成否不明 | 遅い応答・タイムアウト後は結果照合。照合できないときは新規Transferを作り直さない |
| 禁止 | 確認前の出庫、二重タップでの二重出庫、印刷による出庫、完了依頼の再出庫 |

## 印刷：取置・POS Receiptとの対応

- 認証された同じアプリの相対パスを、接続済みプリンタへ1回送信する。
- 未接続・用紙エラーは操作を案内する。送信タイムアウトは成否不明として扱い、遅い送信が決着するまで同一文書を再送しない。自動再印刷はしない。
- 帳票は依頼番号・出庫元・移動先・希望日・備考・依頼数・検品／実数・差異理由を、保存済みスナップショットから描く。未保存の検品は「検品を保存」してから印刷する。
- 設定で58mm／80mm、標準／mPOP 58mm／MCP31LB 58mmを選ぶ。未設定は従来の標準。
- 58mmでは取置と同じviewport（mPOP 400px、MCP31LB 600px）とMCP31LBの横幅補正を適用。80mmは標準の形状にする。補正は二重適用しない。
- POS Receiptの帳票編集全体や精算金額欄の追加は本依頼の対象外。出庫依頼は依頼書のまま扱う。

## 品質確認・未確認事項

自動確認は、管理画面の絞込み・ページ・作成／公開・権限・状態別操作、検索とスキャン、差異確認前の書込み禁止、確定の二重タップ、251明細の分割・結果不明時の照合、印刷の未接続／タイムアウト／二重送信と58／80mmの補正を含める。

独立レビューではUI_RULES・仕入・ロス・通常出庫・現行取置／POS Receiptの実処理と比較する。確認結果・本番反映SHA・Shopify有効版はPRと連絡帳Issue #79に記録する。

**実機で未確認**：iPhone／iPadの固定領域・キーボード、実カメラ／ハードウェア、mPOP／MCP31LBの紙出力、実データの出庫から既存入庫での受領。この資料では検証済みと表現しない。

## 2026-11-26 追加指示：作成タブの商品追加3手段

- 仕入の「商品検索／コレクション検索／CSVアップロード」を作成・編集へ追加する。`product-add-parts.tsx` の方法タブ・候補行・候補一覧・CSVテンプレートを仕入と出庫依頼で実際に共用する。
- 商品検索は商品名・SKU・JAN、候補の選択と数量、選択済み表示、全選択・全解除、候補のページ送りを提供する。
- コレクション検索→商品選択モーダル→候補内検索・選択済み・全選択／解除・数量・50件ごとのページ送り→明細へ追加。取得は公式のproductVariants collectionフィルターを使い、250件で黙って切らない。3000件を超える場合は案内して追加しない。
- CSVはSKU,数量のテンプレートとアップロード。引用符・カンマ・BOM・改行を扱い、空欄数量だけを1にする。不正値、同じCSV内の重複SKU、Shopify側で同じSKUが複数の商品を勝手に解決しない。正常行・行別エラーを表示し、選択した正常行だけを追加する。
- 追加済み商品は二重追加しない。選択だけで保存・公開・在庫変更はしない。検索・CSVなどの取得後も未保存の数量・備考を保持し、保存の帯の「破棄」で候補と入力を戻す。
- 「依頼を追加」の色は追加の利用者指定を優先して青とし、共通主ボタン全体の色は変えない。

API参照: [productVariants（2026-01）](https://shopify.dev/docs/api/admin-graphql/2026-01/queries/productVariants)。
