# POSタイルの未対応件数

入庫・棚卸・出庫依頼は、現在のPOS店舗に未対応がある場合、サブ見出しを **未対応 N件** と表示する。商品／SKUの点数ではなく、次の単位で数える。

| タイル | 対象 | 除外 |
|---|---|---|
| 入庫 | 現在店舗宛てのTransferで、未受領のShipmentがあるもの。伝票1件につき1件 | 移管完了・取消・全数受領・全Shipment受領済み・Shipmentなし |
| 棚卸 | 現在店舗の未完了の棚卸ID。下書き・作業中を含む | 完了・取消。全グループ取消／削除等は既存一覧と同じ補正で完了扱い |
| 取置（期限超過 N件） | 現在店舗の受取期限を過ぎた未完了の取置。保存済みタイムゾーンで当日より前の日付を集計 | 期限当日・期限前・sold・cancelled・failed |
| 出庫依頼 | 現在店舗が出庫元の依頼中・作業中・出庫処理中・要確認・再開待ち | 下書き・出庫完了・取消 |

取置だけは「期限超過 N件」を表示する。次回連絡予定日を延長しても受取期限超過は集計する。既存の要フォロー条件・`count`と未完了件数`pendingCount`は変更せず、専用`overdueCount`を使用する。顧客・商品情報は取得しない。

0件なら各タイルの既存説明（処理・履歴／登録・履歴／確認・印刷・出庫）を表示する。取得失敗・利用不可・店舗未取得でも説明へ戻し、古い店舗の件数や架空の0件を出さない。タイルを押した後の画面や在庫処理は変更しない。

## 更新

- 初回表示、60秒ごと、画面への復帰時に再取得する。
- POS店舗変更は1秒ごとに確認し、変わったら前の件数を消して取得し直す。
- 同店舗の取得処理は重ねない。旧店舗・終了した画面の遅い応答は捨てる。
- 入庫・棚卸は既存プラン判定、取置・出庫依頼は既存の認証／店舗／プラン制御を通す。

## 件数取得

入庫は全Transferページを読み、表示件数の設定で打ち切らない。先頭のShipmentが受領済みでも続きを確認し、未受領があれば伝票を1件とする。既存入庫一覧と同様、未受領の下書きShipmentも対象とする。重複IDはまとめる。

棚卸は軽量一覧メタフィールドを優先し、全チャンクを最大4並列で読む。旧形式では既存の読み取り専用ローダーへ戻す。商品データの取得・countNameの補完・状態の修復保存・在庫変更は行わない。JSON不正やチャンク欠落時は取得失敗とし、部分的な合計を表示しない。
