# 管理画面：棚卸モーダルで商品リスト読み込み中に一括確定・一括キャンセルした場合の挙動

**質問**: 棚卸IDの商品リストを読み込み中に一括確定処理や一括キャンセル処理をしてしまった場合、どのようになるか。

---

## 1. 一括確定（読み込み中に押した場合）

### 現在の実装

- **一括確定ボタンは、商品リストの読み込みが完了するまで無効（disabled）** になっている。
- 条件: `stillLoadingIncomplete` が true のとき（未完了グループのうち、まだ get_incomplete_group_products の応答が返りきっていないグループがある）は `canConfirmAll` が false となり、ボタンが押せない。
- 表示: 読み込み中は「一括確定（読込中）」と表示され、ツールチップで「商品リストの読み込みが完了してから確定できます」と出る。

### 結論

- **通常は読み込み中に一括確定を実行することはできない**（ボタンが押せない）。
- 読み込みが完了した時点で「一括確定」が有効になり、そのタイミングで押すと、取得済みの未完了グループ分だけがサーバーに送られ、一括確定される。

---

## 2. 一括キャンセル（読み込み中に押した場合）

### 現在の実装

- **一括キャンセルボタンは、読み込み中でも有効** である（`disabled` は「完了済み」または「送信中」のときのみ）。
- そのため、**商品リストの読み込み中に一括キャンセルを押すことは可能**。

### 押したあとに起こること

1. **サーバー側**
   - `cancel_stocktake` が実行され、該当棚卸のステータスが「キャンセル」または「完了」に更新され、`cancelledGroupIds` などが書き換わる。
   - レスポンスで `ok: true` が返る。

2. **クライアント側**
   - `historyActionFetcher.data` で成功を受け取り、`revalidator.revalidate()` が走る。
   - 一覧用の loader が再実行され、`inventoryCounts` が最新（キャンセル済み）になる。

3. **モーダル表示の同期**
   - 「モーダル表示中の棚卸を loader の最新データと同期する」effect により、`modalCount` が最新の `inventoryCounts` の内容で更新される。
   - その結果、**モーダル上のステータス・キャンセル済みグループ表示は「キャンセル済み」に切り替わる**。

4. **読み込み中だったリクエストについて**
   - すでに送信済みの `get_incomplete_group_products` は、キャンセル後もそのまま応答が返ってくることがある。
   - 返ってきた応答は `lastSubmittedForModalRef` と一致する場合のみ処理されるため、**「今回のモーダルオープンで送ったリクエスト」の結果はこれまでどおり 1 件ずつ反映される**。
   - そのため、キャンセル後に「まだ読み込み中」だったグループの商品リストが、後から表示されることがある。

### 結論

- **一括キャンセルは読み込み中でも実行でき、サーバー上は正しくキャンセルされる。**
- モーダル上もステータスは「キャンセル済み」に更新される。
- 読み込み中だったグループについては、そのあとで get_incomplete_group_products の応答が返ると、そのグループの商品リストが後から表示されることがある（表示のタイミングがずれるだけであり、データの不整合はない）。

---

## 3. まとめ

| 操作             | 読み込み中に押せるか | 押した場合の結果 |
|------------------|----------------------|------------------|
| **一括確定**     | 押せない（無効）     | ボタンが有効になるまで押せない。有効になってから押すと、取得済みの未完了グループ分が一括確定される。 |
| **一括キャンセル** | 押せる               | サーバー上は正しくキャンセルされ、モーダルのステータスも「キャンセル済み」に更新される。読み込み中だったグループの商品リストは、応答が返り次第、後から表示されることがある。 |
