# 管理画面の UI ルール（確定版 v1.0）

> 正本は T の Doc（https://claude.ai/artifact/HJKZiW8SdoG5aV2MphsFDj）、この写しは v1.0（2026/11/21）。写しと正本が違うときは正本に合わせ、この写しを直す。

2026/11/21 · T

Shop Point の管理画面で実装し、T さんが検証で確かめた決まりをまとめた確定版です。POS Stock・POS Receipt など、ほかのアプリもこのルールで作ります。前提は Shopify の審査基準（Built for Shopify 4章「デザイン」）を守ることで、そのうえで VIP の管理画面のように短く見やすくします。

## 1. 部品の選び方

- Shopify に部品があるものはそれを使う（Polaris web components の `s-` タグと App Bridge）。自前の見た目を作るのは、上部メニューなど Shopify に無いものだけ。
- 色は意味で決める。緑＝有効・完了、青＝これから・処理中、黄＝要確認、赤＝失敗と取り消せない操作、灰＝停止・終了。飾りに色を使わない。

## 2. 画面の形

画面の役割で、3つの形を使い分けます。迷ったら「入力して保存するなら1、1件を見るなら2、並べて見るなら3」です。768px 未満はどの形も縦に1列です。

| 形 | 使う画面 | 例 |
|---|---|---|
| 1. 左に見出し＋1〜2文の説明、右に白いカード | 入力して保存する設定 | 設定の区分、誕生日、友達招待のルール |
| 2. カード2列（左に主な内容、右に要約） | 1件を見る詳細とホーム。スマホでは要約が上 | 会員の詳細、ホーム |
| 3. カード1列、見出しと説明はカードの中 | 幅が要るもの、上から順に読むもの | 一覧、表、履歴、レポート、データの入口 |

| 対象 | 幅 |
|---|---|
| 本文 | 最大 1200px、左右の余白 16px |
| 形1 | 左の説明 1 : 右のカード 2（左 240px 以上、右 320px 以上） |
| 形2 | 右の要約 280〜360px、左は残り全部 |
| 形3 | 本文の幅いっぱい |
| 表の数値・金額・日付・操作の列 | 中身の幅、折り返さない。数値と金額は右寄せ |
| 表の名前・説明の列 | 残りの幅（8文字以上） |

- 設定は「1行の要約＋編集」の一覧に並べ、入力は1区分だけの編集画面で行う（親の URL の下、左上に「←」）。1枚の大きなフォームにしない。入力が5つを超えるときは見出しのあるカードに分ける。

## 3. メニューと移動

- Shopify の左のアプリメニュー（`s-app-nav`）を必ず使う。編集画面でも親の項目を選択中にする。
- 本文上部のメニューは VIP 風で、選択中は背景の色で強調する。スマホは1行の横スライド。公開版の審査では外すことがある。
- ページ内タブは同じ画面の中身を切り替えるときだけ使う。項目ごと・ランクごとにタブを分けない。
- 下の階層からは、タイトル上の「←」だけの枠なしボタンで戻る。
- 下の画面へ移る行は、行全体を押せるようにして右端に「›」を付ける。

## 4. ボタンとリンク

- リンクに下線を付けない。「編集」などの操作はボタンにする。ページ下部に文字だけのリンクを置かない。
- ボタンは Shopify と同じ大きさ（高さ 28px、スマホ 40px）。ボタンだけの行を作らず、見出しの右・説明の下・行の右端に置く。
- ボタンの文字は「動詞」か「名詞＋動詞」で短くする（保存、施策を追加、書き出す）。

| 種類 | 使う場面 |
|---|---|
| 主ボタン（黒） | 画面の一番の操作。1画面に1つ（「施策を追加」「ランクを追加」） |
| 白いボタン | ふつうの操作（行の「編集」、「商品を選ぶ」「書き出す」） |
| 枠なしボタン | 控えめな操作（やめる、もっと見る、「←」） |
| 赤いボタン | 取り消せない操作だけ。確認の窓の中にだけ置く（「削除」「付与する」） |
| アイコン付きボタン | 追加・書き出し・取り込みだけ |
| アイコンだけのボタン | 行の削除（ゴミ箱）、並べ替え（上・下の矢印）、「…」、見出し横の「ⓘ」。触れると名前が出る |

- 表の行の削除はゴミ箱マークだけにする。1件の編集画面では下に「削除」ボタン。
- 取り消せない操作は確認の窓を出し、何がどうなるかを1文で書く。取り消せない入力（誕生日の登録など）も、登録前に窓で確認する。
- 押してから終わるまでは、そのボタンを読み込み中にし、二重に押せないようにする。

## 5. 状態・お知らせ・文章

- 状態は文字でなくバッジで出す。言葉はアプリの中で揃える（有効／開始前／停止中／終了／下書き／要確認／失敗）。
- 「未設定」は本当に何も保存していないときだけ使う。保存済みでまだ始まらないものは「開始前」にし、あと何を保存すれば始まるかを区分の名前で書く（例:「あと「返品のとき」を保存すると、付与と利用が始まります。」）。
- お知らせ枠は1画面に1つまで。重なるときは失敗、注意、案内の順に1つだけ出す。見出しは何が起きたか、本文はどうすればいいかを書く。
- 失敗したときは理由を書く（「入力を確認してください」だけにしない）。どの欄か・どの行かが分かるときは名前を出し、Shopify 側の理由（権限・混雑など）も分けて書く。理由はサーバーの記録にも残す（顧客の値は残さない）。
- 説明は1〜2文。何段落もの説明を画面に出さない。欄の名前は、それだけで意味が分かる言葉にする。
- まだ何もない一覧は空の表示（見出し＋1文＋最初の操作のボタン）。絞り込みの結果が空のときは文字だけにする。

## 6. 入力

- 単位は欄の中の右端に出す（円以上・%・pt・日）。補足は欄の下の薄い文字にし、見出しの括弧に説明を詰めない。
- 選択肢が2〜5個ならラジオ、6個以上ならプルダウン。保存して効くものはチェックボックス。
- 多くの中から選ぶもの（商品・店舗・顧客）は、Shopify の選択画面か、検索付きの選択リストにする。ID の手入力は読み取りに失敗したときだけ。
- 同じ項目を並べて決めるもの（ランクなど）は、1行1件の入力表にする。行の順は人が並べた順のまま保存し、勝手に並べ替えない。並べ替えは行の矢印で行う。
- 日付欄は枠からはみ出さないようにする（iPhone Safari も）。

## 7. 保存

- 保存は Shopify の保存の帯を使う。値が保存したときと違うときだけ上部に「破棄」「保存」を出し、画面の中に保存ボタンを置かない。
- 帯は一度に1つしか出せないので、一緒に決める値は1つのフォームにまとめ、1回の保存で全部を保存する。行ごとに別々のフォームにしない。
- 保存の前に全部の入力を確かめ、1つでも誤りがあれば何も保存しない。途中まで保存された状態を作らない。どうしても段階に分かれるときは、どこまで保存したかを画面で知らせる。
- 入力を黙って捨てない。画面に出ていない欄の値が来たとき、受け取れない値が来たときは保存を断り、理由を出す。
- 成功はトーストで出し、保存のたびに出す。失敗は消えるトーストにせず、画面の赤いお知らせと欄の下の赤い文字に残す。失敗したあとは帯をもう一度出し、そのまま保存し直せるようにする。
- 未保存のまま別の画面へ移るときは、Shopify の確認を出す。

## 8. 一覧と表

- 表はカードからはみ出さず、列が1〜3文字ずつ折り返さないようにする。スマホは横スクロールさせず、1件1枚のカードにする。
- 人の一覧は VIP 風の行にする（頭文字の丸、名前とメール、ランクのバッジ、右寄せの数字と下に小さく項目名、右端に「›」）。行全体を押すと詳細へ移る。探す欄1つと、絞り込み・並び替えの選択を上に置く。件数を上に、ページ送り（‹ ›）を下に出す。
- 名前やメールは Shopify から表示のたびに読み、アプリには保存しない。読めないときは顧客 ID で出し、理由を1行書く。
- 形式を揃える。日時は「2026/11/20 18:30」、ポイントは「1,200 pt」、金額は「¥1,200」、空は「—」。

## 9. レポートとグラフ

- 上に数字のタイルを4つまで置き、下に1行の補足を付ける。その下に、指標1つにつきグラフ1枚。
- 軸は1本だけにする（単位の違う値を1枚に重ねない）。推移は線、増えた・減ったは 0 を挟んだ上下の細い棒、内訳は細い横棒と割合で出す。
- 色は青（#2a78d6）と橙（#eb6834）の2色で、赤・緑は使わない。値はホバーの吹き出しで読ませ、全部の数字を書かない。
- 期間の欄（開始日・終了日など）は同じ幅にする。日ごとの細かい表は画面に出さず、書き出し（CSV）に入れる。履歴は確定したものだけ出す。

## 10. ストアに出さないもの

- 開発・検証・システム確認のための文言と要素（照合のタブ、受付番号、試算、検証用の画面、データ範囲の説明など）は、ストアの管理画面に出さない。検証ストアでしか開けないようにするか、消す。
- 文言だけでなく、画面の中身・ボタン・タブも同じ基準で見直す。

## 11. POS とお客様アカウント

- POS は POS Stock のロス画面を基準にする。本文全体を標準の余白で囲み、見出し・残高・入力・エラー・ボタンの左右の端を揃える。
- お客様アカウント画面は管理画面とは別の部品の組で、このルールの対象外。

## 12. 確認項目

- [ ] iPhone 幅・キーボード表示・縦スクロールと PC 幅で、入力・保存・エラー・再表示を確かめた
- [ ] 1画面に保存の帯が1つで、1回の保存で全部が保存される
- [ ] 保存のあと、値を変えずに帯が出直さない。失敗のあとは出し直す
- [ ] 失敗の文に理由がある（欄・行・Shopify 側の理由）
- [ ] お知らせ枠が1画面に1つまで。状態はバッジ
- [ ] 並べた順が保存のあとも変わらない
- [ ] 開発・検証の文言と要素がストアの画面に残っていない
