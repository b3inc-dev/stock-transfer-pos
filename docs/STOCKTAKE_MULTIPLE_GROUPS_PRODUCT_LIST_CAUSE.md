# 棚卸「まとめて表示」で2つ目以降の商品リストが読み込まれない要因

**日付**: 2026-02-16

## 事象

- 本番で棚卸の「まとめて表示」を使うと、1つ目の商品グループのみ商品リストが表示され、2つ目以降は「商品がありません」のままになる。
- 「商品グループごとに選択」で該当グループを開くと、そのグループの商品リストは表示される。

## 要因

### 1. 棚卸作成時に `inventoryItemIdsByGroup` が全グループ分入っていない

**流れ:**

- POS の「まとめて表示」では、`count.inventoryItemIdsByGroup` を参照して、**グループごとの inventoryItemId 一覧**で商品を取得している（`fetchProductsByGroups` → `savedInventoryItemIds`）。
- `inventoryItemIdsByGroup` は**管理画面で棚卸IDを発行したとき**に、その時点の「商品グループ」の `inventoryItemIds` をコピーして保存している。
- 管理画面のロジックでは、**「グループに既に `inventoryItemIds` が入っているときだけ」** そのグループを `inventoryItemIdsByGroup` に載せていた。

```ts
// 旧ロジック（要因）
if (group.inventoryItemIds && group.inventoryItemIds.length > 0) {
  inventoryItemIdsByGroup[groupId] = [...group.inventoryItemIds];
}
```

- 商品グループの `inventoryItemIds` は、
  - そのグループを**編集して保存**したとき（コレクションやSKUから商品を取得したとき）、または
  - CSVでSKUを登録したとき  
  にだけセットされる。
- そのため、
  - 1つ目のグループは過去に編集保存されていて `inventoryItemIds` がある → 棚卸作成時に `inventoryItemIdsByGroup` に含まれる → POS で商品リストが読める。
  - 2つ目以降のグループは「名前＋コレクション選択だけ」で、一度も「保存」で商品取得していない → `inventoryItemIds` が空 → 棚卸作成時に `inventoryItemIdsByGroup` に**含まれない** → POS では `inventoryItemIdsByGroup` にキーが無いため、コレクション取得にフォールバックするが、POS 側の `readProductGroups()` のグループに `collectionIds` が無い／別要因で 0 件になる → 「商品がありません」になる。

まとめると、

- **「棚卸作成時点で、そのグループに `inventoryItemIds` が入っていないと、`inventoryItemIdsByGroup` にそのグループが載らない」**
- その結果、POS のまとめて表示では 2つ目以降のグループ用の商品リストが取得できず、商品が表示されない。

### 2. 既存の棚卸IDについて

- すでに発行済みの棚卸IDは、**発行時に上記の旧ロジックで保存されている**ため、`inventoryItemIdsByGroup` に 2つ目以降が入っていない可能性が高い。
- そのため、
  - **新規に発行する棚卸ID**は、今回の管理画面側の修正により、全グループ分の商品IDが入るようになる。
  - **既存の棚卸ID**は、現状のままだと 2つ目以降が空のままなので、「まとめて表示」では 2つ目以降が「商品がありません」のままになる。

## 対応内容（コード側）

1. **管理画面（棚卸ID発行時）**
   - 発行時に「選択した全商品グループ」について、その時点で `inventoryItemIds` が空でも、
     - コレクションがあればコレクションから、
     - なければ SKU から  
     商品を取得して `inventoryItemIds` を組み立て、**全グループ分**を `inventoryItemIdsByGroup` に保存するように変更した（`getInventoryItemIdsForGroup` を追加し、発行処理で利用）。
   - これにより、**新規発行する棚卸ID**では、まとめて表示で全グループの商品リストが読まれるようになる。

2. **既存の棚卸ID**
   - コードでは「既存の count を書き換える」処理は入れていない。
   - 既存の棚卸で 2つ目以降も表示したい場合は、
     - その棚卸を**使わず、あらためて棚卸IDを発行し直す**か、
     - 必要であれば「既存棚卸の `inventoryItemIdsByGroup` を補完する」機能を別途検討する必要がある。

## 確認方法

- 管理画面で**新しく棚卸IDを発行**し、複数商品グループを選択して発行する。
- POS でその棚卸IDを開き、「まとめて表示」を選ぶ。
- 全グループで商品リストが表示されることを確認する。

## 管理画面が 502 になる要因（発行直後に発生した場合）

棚卸ID発行後、管理画面が 502 Bad Gateway になることがある。

**想定要因**

- 発行時に「全グループ分の inventoryItemIds」を取得するため、グループ数 × コレクション数ぶんの GraphQL が**直列**で実行される。
- グループが多く、かつ各グループに `inventoryItemIds` が未保存（コレクション/SKU からその場で取得）だと、処理時間が長くなり、**ホスティングのリクエストタイムアウト（例: Render 30 秒）を超える**と 502 になる。
- その間ブラウザは待ち続けるため、発行ボタン押下〜しばらくしてから 502 になる、という動きになる。

**対応（コード側）**

- 取得処理に**時間予算**（例: 22 秒）を設け、超えたら残りのグループはスキップし、取得できた分だけ `inventoryItemIdsByGroup` に載せて棚卸を保存する。
- グループごとに **try/catch** し、1 グループで失敗しても他は続行し、取得できたグループだけ保存する。

これにより、タイムアウトによる 502 を避けつつ、可能な範囲で全グループ分を保存する。  
グループ数が多くて時間内に終わらない場合は、「商品グループ設定」で各グループを一度編集保存（コレクションから商品取得）してから棚卸IDを発行すると、既存の `inventoryItemIds` が使われて発行が軽くなる。

### 39 グループ・約 5800 商品で「Application Error」になる要因と対策（2026-02）

- **要因**: ①発行処理のどこかで未捕捉の例外（GraphQL エラー・メタフィールド保存失敗・ネットワーク等）が発生すると Remix の ErrorBoundary が表示され「Application Error」になる。②メタフィールド値の合計が大きすぎる（39 グループ×約 5800 の inventoryItemId を保存すると JSON が 500KB 超になりうる）と、保存失敗やリクエストタイムアウトで例外になる。
- **対策（実装済み）**: ①`create_inventory_count` 全体を try/catch で囲み、例外時は「棚卸IDの発行中にエラーが発生しました。時間をおいて再度お試しください。」を返して Application Error を出さない。②保存前の JSON サイズが 500KB を超える場合は、その棚卸だけ `inventoryItemIdsByGroup` を保存せず（`inventoryItemIdsOmittedDueToSize` を付与）、棚卸は発行成功とする。POS ではコレクションから商品を読み込む。③時間予算を 22 秒→25 秒に延長してタイムアウトを少し緩和。

## 「まとめて表示」で読めないグループが、グループごと表示のあとだと表示される理由

**事象**: まとめて表示では一部の商品グループだけ読み込みできていない。いったん「商品グループごとに表示」でそのグループを開いてから、再度「まとめて表示」にすると、そのグループが表示される。

### 想定される要因

1. **初回まとめて表示での直列処理とタイムアウト・エラー**
   - 「まとめて表示」では、グループごとに **for ループで直列に** `fetchProductsByGroups` を呼んでいる（`InventoryCountList.jsx`）。
   - 1つ目のグループの取得に時間がかかると、2つ目以降の処理開始が遅れる。その時点で **GraphQL の 20 秒タイムアウト**（`stocktakeApi.js` の `graphql()`）やネットワークの一時的な失敗が起きると、そのグループだけ `products.length === 0` となり、`continue` でスキップされ表示されない。
   - 「商品グループごとに表示」では **1グループだけ** `fetchProductsByGroups` が呼ばれるため、1回の取得で済み、タイムアウトやエラーが起きにくい。
   - 再度「まとめて表示」にしたときは、端末やネットワークが落ち着いている、または前回の処理でメタフィールド取得などが済んでいるため、同じグループも含めて読めるようになることがある。

2. **`inventoryItemIdsByGroup` にキーが無い場合のフォールバックの不安定さ**
   - 当該グループが `inventoryItemIdsByGroup` に含まれていない（既存棚卸 or 発行時の 502 でスキップされた）場合、POS は `readProductGroups()` のメタフィールドから `group.collectionIds` で商品を取得する。
   - 初回の「まとめて表示」で、`readProductGroups()` の GraphQL が一時的に失敗したり、メタフィールドの取得が遅れて空や不完全な結果になると、そのグループは `targetGroups.length === 0` となり 0 件になる。
   - グループごとでそのグループを開くと、**その 1 回だけ** `readProductGroups()` が呼ばれ、そのタイミングでは成功して商品が取れる。再度まとめて表示にすると、同じ `readProductGroups()` が安定して成功し、全グループが表示される。

3. **ID 形式の照合**
   - `count.productGroupIds` と `readProductGroups()` が返す `group.id` の形式（GID と数値など）が一部で一致しないと、`findInventoryItemIdsByGroupKey` / `targetGroups` の filter でそのグループが含まれず 0 件になる。正規化（`normalizeIdForMatch`）で吸収しているが、エッジケースで初回だけ不一致になる可能性がある。

### 運用上の対処

- **新規発行**では、発行時に全グループ分の `inventoryItemIdsByGroup` が入るため、まとめて表示で安定して読める。
- 既存の棚卸で「まとめて表示」の初回だけ一部読めない場合は、**一度「商品グループごとに表示」で該当グループを開いてから「まとめて表示」に戻す**と、多くの場合で表示される。
- 恒常的に読めないグループがある場合は、当該棚卸を発行し直すか、管理画面の「商品グループ設定」でそのグループを編集保存してから、棚卸IDを再発行することを検討する。

## まとめて表示で不備なく表示するためのコード改善（実装済み）

**目的**: 初回の「まとめて表示」でも全商品グループが読み込まれるようにする。

### 1. 商品グループ一覧の事前取得（1回だけ）

- **変更箇所**: `InventoryCountList.jsx`（まとめて表示モード）、`stocktakeApi.js`（`fetchProductsByGroups`）。
- **内容**: まとめて表示のループの**前**に `readProductGroups()` を **1回だけ** 呼び、取得した配列を `cachedProductGroups` として保持。各グループの `fetchProductsByGroups` 呼び出し時に `opts.cachedProductGroups` として渡す。
- **効果**: 全グループが**同じスナップショット**を参照するため、「2つ目以降のグループでだけ `readProductGroups()` が失敗する／遅れる」といったばらつきを防ぎ、初回から安定して表示しやすくする。

### 2. fetchProductsByGroups の cachedProductGroups オプション

- **変更箇所**: `stocktakeApi.js` の `fetchProductsByGroups`。
- **内容**: オプションに `cachedProductGroups`（商品グループ配列）を追加。渡された場合は `readProductGroups()` を呼ばず、この配列を使って `targetGroups` を組み立てる。
- **効果**: まとめて表示時に N 回呼ばれても、商品グループ取得の GraphQL は**事前の1回のみ**で済み、負荷と失敗ポイントを減らす。

### 3. 未完了グループの 0 件リトライ

- **変更箇所**: `InventoryCountList.jsx`（まとめて表示モード・未完了グループの商品取得）。
- **内容**: 未完了グループで `fetchProductsByGroups` の結果が 0 件の場合、**約1秒待機**してからもう1回だけ同じ条件で `fetchProductsByGroups` を実行。2回目も 0 件ならそのグループはスキップする。
- **効果**: 一時的なメタフィールド取得の遅れやネットワーク揺れで 0 件になった場合に、リトライで表示される可能性を高める。

### 確認方法

- 複数商品グループを持つ棚卸IDで、**いきなり「まとめて表示」**を選択する。
- 全グループで商品リストが表示されること、および「商品グループごとに表示」を経由しなくても初回で表示されることを確認する。
